# 营业信息去重（2026-11-02）

## 用户反馈

> 底部「营业 10:00 — 20:00（周一休息）· 建议提前 3 天预约」这些信息有冗余啊，把重复的优化融合到一块。

## 问题定位

同一条信息在**三个紧挨着的区块**各说一遍（About → 预约区块 → 页脚，同一屏内）：

| 位置 | 原来写了什么 |
| --- | --- |
| About「到店须知」 | 4 条：只剩我一个人+一天三位+提前 3 天约 / 营业时间 / 地址 / 款式 |
| 预约区块 | 3 条清单：营业、预约提前量、地址 |
| 页脚 | 1 行：营业 + 预约提前量 |

`hours` 出现 3 次，`addressNote` 2 次，`leadTime` 3 次。

**顺带发现的真缺陷**：About 里的「请尽量提前 3 天约」是硬编码字符串，
而 `site.ts` 另有 `leadTime: '建议提前 3 天预约'`——同一件事两种措辞，
改配置不会同步。这正是重复写法导致的配置漂移。

## 处理原则

**每条信息只在一个地方出现，且必须是它该在的那个地方。**

| 区块 | 职责 | 改动 |
| --- | --- | --- |
| About「到店须知」 | 营业信息的**唯一出处** | 4 条 → 3 条，营业+接待量+预约合并为一条 |
| 预约区块 | 只负责「怎么联系」 | 删掉 3 条清单，只留标题 + 微信号卡片 |
| 页脚 | 品牌 / 导航 / 版权 | 删掉营业那行，去掉一层多余的 div |

三条信息本来就互为因果（只有一个人 → 一天最多三位 → 所以要提前约），
合并成一句读起来更顺：

```
营业与预约    10:00 — 20:00，周一休息 · 一天最多三位 · 建议提前 3 天预约
地址          确认好时间后，微信发你具体位置
关于款式      自带参考图或作品编号都能聊，卸甲免费
```

## 配置层改造

`data/site.ts` 里三个事实拆成私有常量，只导出一个合成结果：

```ts
const HOURS = '10:00 — 20:00，周一休息';
const DAILY_CAPACITY = '一天最多三位';
const LEAD_TIME = '建议提前 3 天预约';

export const CONTACT = {
  wechat: WECHAT_ID,
  hoursNote: `${HOURS} · ${DAILY_CAPACITY} · ${LEAD_TIME}`,  // 全站只输出这一条
  addressNote: '确认好时间后，微信发你具体位置',
} as const;
```

原来单独导出的 `hours` / `leadTime` 不再对外暴露，组件想重复拼也没有字段可用。
同时删掉了从未被任何组件引用的 `CONTACT.booking`。

## 顺带修的排版问题

删掉一条后，「到店须知」卡片被 `.about__grid` 的 `align-items: stretch`
拉伸到与左栏等高，底部多出 76px 空档。加 `align-items: start` 让卡片按内容收紧，
空档回到正常的内边距 29px。

## 死代码清理

`.booking__facts` 的 3 条 CSS 规则（492 字符）随清单一起删除。

## 验证

- `npm run check:booking`：**38/38 通过**（原 31 项 + 新增 7 条去重断言）
- 新增断言：营业时间/提前量/接待量各只出现 1 次、归口在到店须知、
  预约区块与页脚不得再含营业字样、到店须知必须 3 条
- `tsc --noEmit` 通过；`next build` 通过，First Load JS 117 kB（与上轮持平）
- 布局实测（无头 Chrome 量盒模型）：1440 / 900 / 390 三档均无横向溢出，
  到店须知卡片高 358 → 312，页脚品牌与导航无重叠、无错位

## 一处取舍

页脚不再有营业时间。若访客直接点导航「联系预约」跳到 `#contact`，
只会看到微信号卡片——营业信息在正上方「关于」区块。若希望页脚保留一行，
改回来只需在 `Footer.tsx` 里加一行 `{CONTACT.hoursNote}`（但会重新引入重复）。
