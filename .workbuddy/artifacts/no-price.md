# 服务项目去掉价格

## 做了什么

需求只有一句「服务项目暂不用带价格」，但价格从配置到渲染到样式到测试到文档贯穿了五层，
只改其中一层会留下死代码或误报的测试。所以五处一起动。

| 文件 | 改动 |
| --- | --- |
| `data/site.ts` | `ServiceItem` 删除 `price` 字段，5 个条目价格全部移除 |
| `components/Services.tsx` | 删掉价格渲染块（含 `¥` 和「起」），重写区块副标题 |
| `app/globals.css` | 行网格三列 → 两列，删除 3 条价格样式 + 媒体查询里 1 条 |
| `scripts/booking-check.cjs` | 「价格带起字」断言反转为 3 条「价格不存在」 |
| `README.md` | 目录树 2 处描述 + 整节改为「改服务项目（不标价）」 |

## 两个值得说的决定

**1. 从类型层删字段，而不是只隐藏渲染**

`ServiceItem` 里没有 `price`，组件就无从渲染价格。比 `display: none` 或注释掉 JSX 稳，
也不会留下"数据还在、只是没显示"的隐患。

**2. 原来的副标题讲的是价格，必须一起改**

原文案：「金额为参考起价：甲型、长度、是否加固都会影响最终价格，到店先确认再动手。」
价格撤掉后这句就成了空话。改成：

> 时长按甲型与加固需求会有浮动。想做的款式和价格，微信问一句就能给你准数。

保留真实有价值的信息（时长浮动），并把「问价格」顺势变成一个咨询入口 ——
这和整站「只留微信」的策略一致。

**3. 测试断言要反过来写**

原来是 `check('价格带「起」字', prices.every(p => p.includes('起')))`，
现在改成 `无价格节点` / `无 ¥ 符号` / `无金额数字` 三条。

如果只是删掉旧断言，那么「样式删了但数据没删」「数据删了但渲染没删」这类半途状态
都测不出来。反过来断言才锁得住。

## 一个提醒

首页 HTML 里搜 `128` 会有 49 次命中 —— 那是 `next/image` 的 `w=128` 图片档位，
**不是价格残留**，别误判。

## 以后要标价怎么办

改三处，缺一不可：

1. `data/site.ts` 的 `ServiceItem` 加回 `price: number`
2. `components/Services.tsx` 加回价格渲染
3. `app/globals.css` 的 `.svc-list__row` 把 `grid-template-columns`
   从 `auto minmax(0, 1fr)` 改回 `auto minmax(0, 1fr) auto`

另外 `npm run check:booking` 里那 3 条「不出现价格」的断言要同步改，否则会红。
