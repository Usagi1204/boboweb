## 网络排障（境内访问 supabase.co）

- 症状：`db:migrate` fetch failed。诊断：supabase.com 走代理 200，
  `*.supabase.co` TLS 握手被 RST；对照其他项目子域同样失败 → 整域问题。
- 根因 1：用户代理客户端规则表缺 `DOMAIN-SUFFIX,supabase.co` → 用户已加。
- 根因 2：代理客户端 HTTP 端口会变（56840 → 6478），shell 缓存的
  HTTP_PROXY 环境变量会过期；项目统一改从 `.env.local` 读 `SUPABASE_PROXY_URL`。
- 根因 3：Node 22 的 `NODE_USE_ENV_PROXY=1` 实测无效（Google 对照实验证实），
  必须用 npm `undici` 的 `fetch` + `ProxyAgent`；且 ProxyAgent 与 Node 内置全局
  fetch 不兼容（UND_ERR_INVALID_ARG / invalid onRequestStart），只能用 undici 自家 fetch。
- storage-js 坑：Node 下传 Blob 会被包进 FormData（空字段名），经 undici 代理
  multipart 序列化时 content-type 丢成 text/plain，被桶 MIME 白名单拒。
  修法：上传体改传 Uint8Array。
- next/image 坑：优化器服务端取图不走代理 fetch，500。修法：
  `next.config.js` 里 `images.unoptimized` 在设置 SUPABASE_PROXY_URL 时为 true
  （本地浏览器直连加载，生产 Vercel 不设该变量保持优化器开启）。
